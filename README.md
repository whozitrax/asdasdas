# GiftRelayer — полная восстановленная сборка (9 октября 2026)

Это полная совместимая сборка, собранная из последних **доступных в переписке** файлов. Изменения, сделанные только в веб-редакторе BotHost и не присланные сюда, прочитать невозможно.

## Что включено

- Администратор создаёт `/offer https://t.me/nft/MoodPack-81539 900 stars` или `/offer https://t.me/nft/MoodPack-81539 1.5 ton`, без отдельного названия.
- Inline Mode: вставить `@GiftSendRelayerBot ID_ОФФЕРА` в нужной переписке, отправить карточку.
- Inline-сообщение может обновляться после принятия: «Предложение принято», кнопка «Открыть сделку». **Нужно включить Inline Feedback → 100% в BotFather**. Telegram иногда не передаёт `inline_message_id`; тогда изменение сообщения недоступно, но оффер работает.
- Blue Mini App с загрузкой, NFT-превью/анимацией, ценой и сроком. В блоке покупателя нет Telegram ID; при наличии `@username` переход в профиль с `?profile`, иначе инструкция свернуть Mini App вручную.
- Авторизация Mini App по подписанному Telegram `initData`; проверка NFT-передачи без ложного подтверждения при недостатке сведений.
- Не используются Telegram Business API и Pillow. **Premium не требуется**. Бот не проводит автоматическую оплату Stars или TON и не является эскроу.

## Установка в существующий BotHost

1. **Сделайте резервную копию** файлов `/app/data/`, особенно `/app/data/giftrelayer_forward.sqlite3`, если они доступны. Архив намеренно **не содержит** папку `data/`.
2. Откройте редактирование файлов текущего проекта BotHost. Загрузите файлы и папки из этого ZIP **в корень `/app`**, не в дополнительную подпапку. Структура приведена ниже.
3. Не заменяйте существующую папку `/app/data` — там сохранены офферы и Premium Emoji. Если решите создать нового бота/проект, перенесите базу отдельно.
4. В настройках переменных окружения BotHost проверьте:
   - `BOT_TOKEN` — **актуальный перевыпущенный токен того же бота**, не добавляйте его в файлы и логи;
   - `PUBLIC_BASE_URL` — HTTPS-адрес вашего BotHost без `/app`, например `https://bot-1791496857-3207-z1trax.bothost.tech`;
   - `PORT=3000` (или порт, который выдаёт BotHost);
   - `DATA_DIR=/app/data`.
5. Основной файл запуска — `main.py`; зависимости — `requirements.txt`. Запуск: `python main.py`.
6. В BotFather включите у этого же бота Inline Mode и Main Mini App c URL `https://<домен>/app`; для редактирования исходного inline-сообщения включите **Inline Feedback 100%**.
7. Запустите проект и проверьте в логах `Web server started` и `BOT STARTED`. В адресе `https://<домен>/health` должен возвращаться JSON с `"ok":true`. Убедитесь, что открытие Mini App проходит из Telegram.

## Важное о контейнере BotHost

Сообщение `Контейнер не найден` при наличии `Successfully built` означает, что сбой может происходить **после** сборки Docker-образа, на этапе создания или привязки контейнера. **Сам ZIP не гарантирует исправления этого сбоя.** Если даже после загрузки сборка проходит, но контейнер отсутствует и рабочих логов нет, обратитесь в поддержку BotHost со скриншотами статуса бота и строкой `Successfully built`; попросите повторно создать контейнер для существующего проекта без удаления данных.

## Локальные проверки

`python -m unittest discover -s tests -v` — проверяет команды, HMAC и SQLite без подключения к Telegram. Для запуска самого бота нужен действующий `BOT_TOKEN` и доступ к Telegram API.

## Безопасность

Не публикуйте `BOT_TOKEN`, `initData`, `.env` и базу данных. Старый токен, ранее попавший в переписку/логи, нужно перевыпустить в BotFather. Никакие статусы оффера не подтверждают получение денег, пока не реализована отдельная верификация оплаты.
